# الكتالوج الافتراضي وصور الأصناف/الأقسام — إضافة على مواصفة `sync/upload`

**الحالة:** مطبّق فعليًا في تطبيق الكاشير (Flutter). المستند ده إضافة (addendum) على مواصفة الرفع الأساسية (`POST /api/v1/sync/upload`) اللي عندكوا بالفعل — بيغطي حالة معينة بس: الأصناف والأقسام الافتراضية اللي جايه مع التطبيق نفسه لكل كافيه جديد.

---

## 1) المشكلة

التطبيق بيجي مع كتالوج افتراضي جاهز (~6 أقسام، حوالي 50 صنف) — شاي، قهوة، عصائر، مياه غازية... إلخ، كل واحد بصورته. الكتالوج ده **متطابق بالحرف على كل تليفون ولكل كافيه** لأنه جزء من التطبيق نفسه (Flutter assets)، مش بيانات مُدخلة من المستخدم.

من غير معالجة خاصة، أول Sync لأي كافيه جديد كان هيرفع نفس الصور دي من الصفر (~50 صورة) — تكرار مالوش داعي، بيكبّر حجم أول رفعة وبيستهلك تخزين على السيرفر لنفس الصور بالظبط لكل كافيه.

## 2) الحل

كل صنف/قسم بقى بيوصل ومعاه 3 حقول إضافية توضح هل هو "افتراضي" ولا لأ، وبناءً عليها الصورة بتتبعت أو لأ:

| الحقل | النوع | الوصف |
|---|---|---|
| `is_default` | `boolean` | `true` لو الصنف/القسم من الكتالوج الافتراضي اللي جاي مع التطبيق. `false` لو المستخدم أضافه بنفسه. |
| `image_key` | `string \| null` | زي المتفق عليه في المواصفة الأساسية — اسم الملف جوا `images.zip`. **دايمًا `null` للعناصر الافتراضية** طالما صورتها لسه الأصلية (لسه ما اتغيّرتش). |
| `local_asset_path` | `string \| null` | **حقل جديد.** المسار الداخلي للصورة جوا حزمة التطبيق (asset path)، زي `assets/images/seed_items/hot_tea_plain.png`. موجود بس لما `is_default = true` والصورة لسه الأصلية؛ غير كده بيكون `null`. |

### القاعدة البسيطة

```
لو is_default = true والصورة لسه الافتراضية:
    image_key = null            (مفيش صورة هترفع، ومفيش ملف ليها في images.zip)
    local_asset_path = "assets/images/seed_items/xxx.png"

لو is_default = true بس المستخدم غيّر الصورة بصورة حقيقية من موبايله:
    image_key = "<uuid>.<ext>"  (زي أي صورة عادية، بتترفع في images.zip)
    local_asset_path = null

لو is_default = false (صنف/قسم أضافه المستخدم بنفسه):
    نفس السلوك الحالي بالظبط — مفيش تغيير
```

يعني القرار بيتحدد من **حالة الصورة الفعلية** مش من `is_default` نفسها — لو صنف افتراضي المستخدم غيّر صورته، `image_key` بيرجع يشتغل عادي تلقائيًا من غير أي تغيير تاني.

## 3) أمثلة

**قسم افتراضي، صورته لسه زي ما هي (الحالة الشائعة في أول Sync):**
```json
{
  "uuid": "9f8e7d6c-...",
  "name": "مشروبات ساخنة",
  "sort_order": 0,
  "is_active": true,
  "is_default": true,
  "image_key": null,
  "local_asset_path": "assets/images/seed_items/hot_tea_plain.png"
}
```

**صنف افتراضي غيّر المستخدم صورته:**
```json
{
  "uuid": "8a7b6c5d-...",
  "category_uuid": "9f8e7d6c-...",
  "name": "شاي عادي",
  "price": "15.00",
  "sort_order": 0,
  "is_active": true,
  "is_default": true,
  "image_key": "8a7b6c5d-....jpg",
  "local_asset_path": null
}
```
(وهنا `8a7b6c5d-....jpg` موجود فعليًا جوا `images.zip` زي أي صورة عادية.)

**صنف أضافه المستخدم بنفسه (مش افتراضي):**
```json
{
  "uuid": "11223344-...",
  "category_uuid": "9f8e7d6c-...",
  "name": "قهوة تركي مضبوطة",
  "price": "25.00",
  "sort_order": 5,
  "is_active": true,
  "is_default": false,
  "image_key": "11223344-....jpg",
  "local_asset_path": null
}
```

## 4) اللي محتاجينه منكم

`local_asset_path` مجرد **معلومة استرشادية** — مش ملف بيترفع، ومش موجود فعليًا عندكم كـ asset في السيرفر. القرار بتاعكم إزاي تتعاملوا مع `is_default = true` و `image_key = null` عندكم — الاحتمالات المطروحة:

1. **تجاهل الصورة تمامًا** للعناصر الافتراضية (تفضل من غير صورة عند السيرفر/الداشبورد لحد ما حد يغيّرها فعليًا).
2. **استضافة نسخة واحدة من الكتالوج الافتراضي عندكم** (بنفس أسماء الملفات اللي في `local_asset_path`، أو بأي مفتاح تانين تحددوه) وربطها تلقائيًا بأي صنف/قسم `is_default = true` بغض النظر عن الكافيه.

الخيار التاني أفضل لو عايزين الداشبورد يعرض صورة، بس محتاج منكم نسخة واحدة بس من الصور دي (مش لكل كافيه) — احنا جاهزين نديكم كل صور الكتالوج الافتراضي كملف واحد لو ده الاتجاه اللي هتاخدوه.

## 5) تذكير مهم (من تجربة فعلية)

الباك إند بيرفض الرفع بـ `422` ورسالة `"The ZIP files must match image_key values exactly"` لو `image_key` اتحط في الـ JSON من غير ما يبقى ليه ملف مطابق بالظبط جوا `images.zip`، أو العكس. إحنا ضمنّا من طرفنا إن الاتنين دايمًا متطابقين (`image_key = null` لأي عنصر مش هيترفعله صورة). لو ظهرت الرسالة دي تاني من عندكم، يبقى فيه احتمال السيرفر بيتوقع سلوك مختلف عن كده.
